# Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-11-20 | PULSE ONE is a new, standalone native app (Swift 6/SwiftUI, RealityKit later) in its own repo. MyBody (Expo, repo MyBotty) stays untouched. Supersedes MyBotty ADR-001 (hybrid). | Owner decision in the project thread 2026-11-20 15:32 UTC: start fresh from the master directive with its own identity. |
| 2026-11-20 | Bundle ID `de.sommerlabs.pulseone`, display name "PULSE ONE". | Owner prefix `de.sommerlabs`; separate identity from MyBody. |
| 2026-11-20 | Build/test/screenshots on GitHub Actions `macos-26` using the ios-studio pipeline (copied, not rebuilt); XcodeGen 2.48.0; Xcode 26.6. | No Mac; free option. Xcode 27 not on the runner yet. |
| 2026-11-20 | Persistence with SwiftData; every value stores unit, timestamp, source, device, model, firmware. No "simulated" source exists. | Directive §10.7, §11; no invented values. |
| 2026-11-20 | Bluetooth permission is requested on the first "Ring suchen" tap, not at launch. Auto-reconnect only when permission already exists. | Directive §10.1; the user sees why before the system prompt. |
| 2026-11-20 | Colmi support is claimed only after the UART service is discovered; capability levels expected → discovered → verified. | Codex review: BLE connected ≠ data works; names alone prove nothing. |
| 2026-11-20 | Dark-only UI until the four design profiles land; screenshot matrix is dark × Dynamic Type. | Cinematic Dark is the base identity (§5.1); Clinical Light is a profile (§7). |
| 2026-11-20 | Live heart-rate measurement stops automatically after 60 s. | Protects the ring battery; keep-alive interval still to be verified on the R03. |
| 2026-11-20 | Heart Chamber heart is procedural (RealityKit `MeshDescriptor` from `HeartGeometry`), no third-party 3D asset. Stylised, not anatomically exact. | No asset licence needed; a licensed anatomical model can replace it later (see docs/ASSETS.md). |
| 2026-11-20 | Heart motion and lub-dub are derived from the BPM value only and are labelled "kein EKG". Live: haptic/sound per beat; stored value: motion only. | Directive §5.3 and honesty rules: no invented ECG signal. |
| 2026-11-20 | Heart sound is synthesised (`HeartSound`), off by default, `.ambient` session (respects silent switch). Haptics on by default. | No audio assets; owner wants sound + haptics, but sound must never surprise. |
| 2026-11-20 | Accessibility audit: `textClipped` issues are ignored; clipping is checked on the xxxl screenshot matrix instead. Contrast issues inside the orb and the 3D heart are ignored. | CI run 3 flagged one-line captions as clipped although the xxxl screenshots show them wrapping completely; rendered visuals carry their own label/value. All other audit types stay blocking. |
| 2026-11-20 | Normalised samples live in SwiftData `StoredSample` with a unique dedup key (source, device, kind, source id). `StoredMeasurement` stays for the current history card until the TODAY screen replaces it. | Idempotent sync and no double counting (GD 3.0 §5) without breaking the working screen. |
| 2026-11-20 | Device registry stored as JSON in Application Support (complete file protection), not SwiftData. | Small, rarely changing list; Codable core type stays testable without SwiftData. |
| 2026-11-20 | Apple Health: read-only, first import limited to 30 days, then incremental per type with HKQueryAnchor; only for the owner profile. Integration stage stops at "synchronisiert"; "Qualität geprüft" needs a real-device check. | GD 3.0 Phase A; Health never reveals denied read access, so an empty import is not proof of access. |
| 2026-11-20 | Legacy `StoredMeasurement` rows are migrated into `StoredSample` once at launch through the same ring mapping as live values; idempotent via the dedup key, marker set only after success, legacy rows kept. | Directive 3.1 A: controlled migration without data loss; repeatable after an interrupted run. |
| 2026-11-20 | Ring samples have no source id: original id = `live|history-<ms>-<kind>`. | Stable key for live values and migration alike; live and history stay separate measurement paths. |
| 2026-11-20 | Timestamps before 2010 or more than 10 min in the future are rejected and logged, not stored. | Unset or wrong device clocks must not create fake history. |
| 2026-11-20 | Source resolution is per origin (source + device) with optional device priority; fallback is device id order. Totals and daily values carry their origin. | Directive 3.1 A "nachvollziehbare Quellenpriorität"; two rings of one model must never be summed. |
| 2026-11-20 | An Apple Health sync without any data keeps the stage at "kompatibel" and shows a permission hint instead of "synchronisiert". | Stages rise only with evidence; Health hides denied read access. |
| 2026-11-20 | Removing a device keeps its stored samples. | History stays traceable; deleting health data needs its own explicit action (to be designed). |
| 2026-11-20 | Device-to-profile assignment is a timeline of periods with reason and record time. Samples take the profile valid at their time; syncs never re-attribute; gaps are unresolved (profileID nil); only a logged correction re-attributes. Supersedes "re-sync updates profile". | Codex Review 3.2 §2. |
| 2026-11-20 | Ring derived identity includes path, ms, interval (when known), kind and value. Overlap between different samples is resolved at evaluation (per minute one origin and one method, live first), never by deleting. | Review 3.2 §3: a timestamp is not a unique id. |
| 2026-11-20 | Source choice: profile preference per kind (device or source system) → automatic order per kind and situation → device priority/id. No "last added wins". Counters merge per hour, intervals per day by union. | Review 3.2 §4, §6. |
| 2026-11-20 | Quality levels valid / plausible (unconfirmed) / implausible / incomplete / time uncertain / technical error, each with a stored reason; only valid and plausible feed analyses. | Review 3.2 §5. |
| 2026-11-20 | Barcode scan and food search may query Open Food Facts and USDA FoodData Central; the services see the scanned product. A setting can turn online lookup off. | Owner decision in the project chat 2026-11-20. |
| 2026-11-20 | Users can enter known diagnoses themselves; shown and, only with per-entry consent, used as analysis context. No automatic coding by the app or Claude. | Owner decision in the project chat 2026-11-20; see CLINICAL-CONTEXT-SPEC.md. |
| 2026-11-21 | Navigation: five tabs Heute · Gesundheit · Analyse · Coach · Ernährung; profile, devices, ring and AI provider in a sheet from the profile button of every tab. Modules plug in via fixed root views (`docs/pulse-one-coordination/INTEGRATION.md`). | DESIGN-SYSTEM-5.0 §2; four teams build in parallel and integrate into one build. |
| 2026-11-21 | Personal band = 25th–75th percentile of the person's own daily values in the 28 days before the reference day, at least 7 days with data. Values outside are marked neutral violet, never red. | Robust with few days, descriptive only (no diagnosis, no prediction); one definition shared by TODAY, HEALTH, Claude analysis and coach. |
| 2026-11-21 | Charts with Swift Charts (Apple framework). Day view hourly for single readings and counters; gaps stay gaps. | No third-party dependency; DESIGN-SYSTEM-5.0 §4 TrendChart. |
| 2026-11-21 | Profile (name, birth year, sex, height, weight) as JSON in Application Support with complete file protection; all fields optional; first-start setup resumable at the saved step and skippable. | Codex P1-003 product order: usable without a device, nothing guessed. |
| 2026-11-21 | Ring measuring profiles: Standard (pulse 5 min, HRV, stress, SpO₂ on), Akku sparen (pulse 15 min, HRV on, stress and SpO₂ off), Minimal (pulse 30 min, only pulse, steps, sleep). Applied on every connect, then read back from the ring. | konzept/RING-AUSWERTUNGEN.md "Standard"; owner asked how often the ring measures. Only Gadgetbridge-documented commands. |
| 2026-11-21 | Ring history is fetched on every connect and when the app comes to the foreground at most every 6 hours (days since last fetch + 1 overlap, 2–7 days). No background Bluetooth. | "Daily" without background modes; repeated values are deduplicated by the derived ring id. |
| 2026-11-21 | Ring features are capabilities by evidence (expected → answered / unsupported), not model names. Skin temperature exists as a capability for models listed with temperature (R09) but sends no command until a real R09 test. | Owner switches to the R09 soon and will add more sensors; the UI shows values by capability. |
| 2026-11-21 | SpO₂ history is stored as one hourly value (midpoint of the ring's min and max, as Gadgetbridge does) with min/max kept in the raw reference; sleep as asleep minutes (all stages except awake) with the stage breakdown in the raw reference. | No new sample kinds needed; nothing invented beyond the ring's own numbers. |
| 2026-11-21 | Accessibility audit ignores contrast findings on elements under the translucent navigation and tab bars (±32 pt) and pixel-only text findings when bars exist; those areas are checked on the screenshot matrix. | iOS 26 bars are glass with content scrolling beneath; the audit measured text through the glass (CI run 36). All other findings still fail the test. |
| 2026-11-21 | Accessibility audit also ignores Dynamic Type findings on buttons inside the navigation bar (toolbar items such as "Anpassen"). | The system draws toolbar items at a fixed bar size and offers the Large Content Viewer; buttons in content still have to scale (PR #26 CI). |
| 2026-11-21 | Accessibility audit ignores contrast findings that carry no element (frame 0×0) on the nutrition screen only. | They cannot be located on screen and appeared only intermittently on a slow runner (PR #32, nutrition); every contrast finding with an element still fails. |
| 2026-11-21 | Ring stress index (Colmi 0x37) is stored as its own kind and shown only as a daily pattern, labelled as a manufacturer value; no single-value rating, not mixed with HRV. Replaces "do not show". | Owner decision 2026-11-21 (QRing gap analysis, QRING-ABGLEICH.md); QRing shows it too, and a pattern view claims no more than the index supports. |
| 2026-11-21 | Claude analysis calls the Messages API directly with URLSession (no SDK, no server of our own). The user's own key lives only in the Keychain (`WhenUnlockedThisDeviceOnly`, not synchronised); UI tests use a canned transport and an in-memory key. | No Swift SDK exists; no backend means health data goes only from the iPhone to Anthropic, and only after the visible send preview. |
| 2026-11-21 | Claude requests are non-streaming with `max_tokens` 16 000, structured JSON output (`output_config.format`), server-side fallback beta, prompt caching on the system prompt; questions use strict local tools (max 8 calls) instead of sending raw data. | Every answer must be validated as a whole before it is shown (numbers, evidence ids, safety rules S1–S6), which streaming would not allow. |
| 2026-11-21 | Evening note: text field with keyboard dictation, rule-based German tag extraction the user confirms; only confirmed tags (never the text) may enter analyses. No Speech framework. | No extra microphone/speech permission; deterministic and testable; free text stays on the device. |
| 2026-11-21 | Apple's on-device model (FoundationModels, iOS 26+, behind `#available`) only rephrases the fixed daily sentences; its text is used only if it keeps exactly the same numbers and passes the safety check, else the fixed sentences stay. | Free and offline "local brain" without risking invented values; iOS 18 devices get the fixed sentences. |
| 2026-11-21 | Monthly brakes for Claude: budget in USD (default 10 $) and a maximum number of sends (default 30), both checked before every call; cost is computed from the token counts Anthropic reports. | Owner approved API costs; the brakes keep them predictable. |
| 2026-11-21 | Ring HRV (0x39) is its own sample kind `hrv_ring`, never `hrv_sdnn`; ring stress is `stress_index_ring` (vendor index 0–100). Both come only from the ring. | QRing gap analysis: the ring's HRV method is undocumented, mixing it with Apple SDNN would compare different measures. |
| 2026-11-21 | TODAY tiles can be hidden and reordered (Anpassen); stored as JSON in UserDefaults; new tiles from later versions are appended. The ring stress index tile is hidden by default. | Owner wants a customizable interface; stress shown only on request as vendor value. |
| 2026-11-21 | The Begleiter tile on TODAY cannot be hidden. | It is the only way to the alarm settings; a hidden tile would leave a ringing alarm without a way to change it (test team). |
| 2026-11-21 | Reminder on TODAY and the ring card from day 4 without a ring history fetch; no push notification yet. | The ring keeps about 7 days; an in-app hint needs no extra permission. |
| 2026-11-21 | Weather for the Begleiter comes from Open-Meteo (forecast, air quality, geocoding), free without API key, data under CC BY 4.0 (source named in the app). Only the chosen place's coordinates, rounded to 2 decimals, are sent; no health data. Cached 1 h. | Body weather and clothing advice need a forecast; Open-Meteo needs no account or key and no paid plan for private use. |
| 2026-11-21 | Begleiter nudges: at most 3 per day, counted over the whole day (a later re-plan never adds more). Without a measured or confirmed wake the day is planned from today's alarm time or 07:00. The Expertenrunde only sends categories switched on under KI-Anbieter (heart and sleep required). | Test-team review: avoid a 4th nudge, nonsense times after an evening first launch, and sending values outside the consent. |
